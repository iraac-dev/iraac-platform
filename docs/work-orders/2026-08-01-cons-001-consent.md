# CONS-001 — Consent capture, receipts and withdrawal

## Goal

Let a survey respondent optionally leave contact details and grant **separate,
unticked** channel permissions (I01–I05), record **versioned receipts** of
exactly what wording they saw, and let them **withdraw or change preferences
without logging in**. Each channel must be independently provable; withdrawal
and global/channel stops must apply immediately and be audit-logged.

## Non-goals

- No real outbound contact (email/SMS/call) — that is P2 scope (MAIL-*).
- No login/auth system (ADMIN-001).
- No change to the anonymous SURV-002 journey — anonymous submission still
  strips H/I; CONS-001 adds the *optional contact* journey as a distinct path.
- No production data — synthetic fixtures only.

## Acceptance tests

1. Survey respondent can opt into contact (H01 = Yes) and complete I01–I05
   with **all boxes unticked by default**; nothing is granted unless ticked.
2. Each granted channel writes exactly one `consent_events` row linking to the
   `consent_wording_versions` row the respondent actually saw (versioned
   receipt); `consent_state` reflects current grants.
3. Anonymous submissions still strip H/I entirely (SURV-002 tests stay green).
4. No-login withdrawal endpoint: a token from the receipt can set
   `suppression_events` (reason=withdrawal, channel or global); the change is
   visible immediately and audit-logged.
5. RLS: anon can insert consent/suppression events for their own token but
   cannot read people/answers; staff can read; auditors read-only. pgTAP
   suite passes 100%.
6. Quality gate green: lint, typecheck, vitest, `next build`.
